SmartEPT — Employee Archive on Delete

Delete an employee → full backup kept, code freed for reuse
Ametecs India Pvt. Ltd.

Prepared for: Ejaz Hussain

Deleting an employee used to simply remove them from the active list. It now does three things automatically, so no history is ever lost and the employee code can be handed to a new joiner straight away.

1 · What happens when you delete an employee

1
The record is archived under a clear label. The deleted person is filed in a new Employee Archive as EmployeeCode_Name_ArchiveDate — for example E-2001_Rahul-Sharma_2026-07-24 — so their identity stays traceable even after the code is reused.
2
A complete backup is taken. Everything tied to that person — attendance, breaks, activity, screenshots, webcam photos, violations, meetings, biometric mappings (about twenty data types in all) — is packaged into a downloadable ZIP: a full record-by-record export plus the actual screenshot and webcam image files.
3
The Employee Code is released. The code is freed the moment you delete, so you can issue the same code to a new joiner. The old person's data stays under their old record and never mixes with the new hire's.
Where to find it. A new Employee Archive panel sits just below the employee list in the Employee tab. Each archived person shows their label, a record count, who archived them and when, and a Download ZIP button. The backup is prepared in the background and shows "Preparing…" for up to a minute, then becomes a download.

2 · What's inside the backup ZIP

ItemContents
employee.jsonThe employee's profile and a record count for every data type.
data/*.ndjsonThe complete record-by-record export — one file per data type (attendance, breaks, activity, violations, meetings, and so on).
screenshots/The actual screenshot images captured for this person.
webcam/Webcam presence photos, if any were captured.
README.txtA plain-language guide to the folder.

The live data is left in place (nothing is destroyed) — the ZIP is a clean, retrievable copy. Backups are built one at a time and streamed in chunks, so even an employee with months of screenshots can't slow down the delete or overload the server.

3 · How it was built & checked

  • Instant delete, background backup. The heavy ZIP is built by a scheduled job (smartept:build-archives, every minute) rather than during the click — so deleting is always fast. No separate queue worker is needed, just the scheduler.
  • Safe by design. Every data table is read defensively, so a missing or renamed table can never turn a delete into an error — the backup is always best-effort complete.
  • Verified here: all server code is PHP lint-clean and the dashboard JavaScript passes its syntax check. The one part to click-test on your live console is the Archive panel + download, since that UI can only be syntax-checked from my side.

4 · To switch it on

  1. Run the migration — migrate.bat (adds the employee_archives table).
  2. Confirm the scheduler is running — the "Background scheduler" tile in Help → Troubleshooting should be green. That's what builds the ZIPs; without it, archives stay on "Preparing…". You can also run php artisan smartept:build-archives once by hand.
  3. Check PHP's zip extension is on (Laragon ships with it). If it's off, an archive row says so clearly instead of failing silently.
  4. Restart PHP / hard-refresh the console.

Backups are saved under storage/app/archives/ — make sure your storage backup covers that folder.
