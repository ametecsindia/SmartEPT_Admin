4. Root causes

The structural root (A4, A6, A7, B1, B2, B3, B15): there was no single authoritative definition of an employee’s current work state — Active/Idle/Break(sub-type)/Meeting/Offline were derived inconsistently in different places, so durations disagreed, exclusivity wasn’t enforced, and the dashboard couldn’t show live break status. Building the status_timeline + StatusService state machine (one open segment, idempotent event processing, mutual exclusivity) fixed the cluster at the source.

The clock root (A5, B12): the agent trusted the local wall-clock, so changing it (or a Mac’s locale-formatted timestamps) corrupted recorded time. The fix is a server-time-offset clock with a monotonic base, so a mid-session clock change can’t distort reported duration.

The gate root (A3): the agent read gate fields at a nesting level the server never returned, so the gate silently passed. The server now returns the fields at the level the agent enforces on, the agent fails closed, and pre-punch capture is refused at ingestion.

The policy-refresh root (B11): the policy bundle was fetched once at login and the screenshot scheduler could stack a second timer on any re-apply — producing “a shot every minute” instead of the configured interval. The agent now clears the old scheduler first and re-resolves policy live. Individual root causes for the remaining defects are in the §3 table.

8. Scheduler / job changes

  • New 1-minute heartbeat closure stamps a cache key; the Troubleshooting Background scheduler tile turns red if schedule:run stops (B6 self-diagnosis).
  • Biometric auto-sync (every 5 minutes) confirmed; a consecutive-failure cap (5) auto-disables a broken feed to ERROR and the Biometric tile flags it.
  • Nightly mark-attendance now finalises the shift-aware checkout (B7) before the half-day rule.

9. Windows agent & service changes (v0.11.0)

  • Clock: server-time offset + monotonic base; every stamp server-corrected (A5).
  • Gate: fails closed; per-reason wall; never starts tracking on an unknown/gated state (A3).
  • Breaks: IPC guards disable conflicting break/meeting buttons; “end current break first” (A6/A7).
  • Exit/uninstall: admin-password exit modal (5-try → lockout), tamper reporting, NSIS uninstall guard (A8).
  • Screenshots: scheduler never stacks timers; applies interval changes live; each shot carries policy id/version/interval + violation correlation id (B10/B11).
  • Login display: renderer never blanks; retains last payload while offline (A1/A2).

10. macOS agent changes (B12)

  • Confirmed the agent payload path uses no locale-dependent date strings — timestamps are hand-formatted and byte-identical across Windows/macOS/Linux.
  • Added a platform-neutral fmtIso() (ISO-8601 with explicit numeric offset) as an additive helper.
  • Violation timestamps now use the server-corrected clock (ordering/correlation hold on macOS).
  • The full switch to offset-carrying stamps on every event is a coordinated server read-side change (D6) and is intentionally deferred to avoid regressing the existing timezone-aware day bucketing (see §20).

11. Dashboard / reporting changes

  • Live status shows work_status with break sub-type + meeting; break/idle/meeting widgets open the filtered live list, never the Attendance tab (B1/B2/B3/B15).
  • Attendance sheet + CSV export surface how check-in/out/late were derived (source columns) (B7/B8).
  • Violations tab: a dedicated evidence modal shows only the violation’s shots (B10).
  • Audit trail: datetime range pickers + CSV export button (B13/B14).
  • Meeting scheduling modal rebuilt on-theme; actions hidden when the role lacks the permission (B4/B5).

12. Config / env changes

No .env or server config changes are required. New operational settings are per-company and admin-editable in the database (attendance late_arrival_source/checkout_policy/checkout_grace_minutes, evidence_window_seconds), consistent with the Ametecs “configure in the UI, stored in DB” standard. The only environmental dependency is the existing requirement that the OS scheduler runs php artisan schedule:run every minute (now self-diagnosing).

20. Known limitations & items needing confirmation

  • A8 / D4 — native tamper-proofing. Absolute protection against a full-Administrator or physical user is not achievable from an Electron/tray app. We ship the strongest supported protection (exit-lock, tamper logging, NSIS uninstall guard, server-authoritative gate). A protected Windows service is a separate, larger build if required.
  • B12 / D6 — clock authority rollout. The agent is server-time-authoritative and macOS-format-safe now. Moving every timestamp to carry an explicit UTC offset (and the server storing UTC + displaying org-local everywhere) is a coordinated server read-side change; it was deferred to avoid regressing the current timezone-aware day bucketing. Confirm whether that full rollout is in scope for a follow-up.
  • B6 — auto-sync depends on the OS scheduler. Cloud biometric auto-sync only runs if Task Scheduler runs schedule:run every minute (now self-diagnosing via the tile). Physical on-prem readers may need a device-specific auto path.
  • Custom roles (B5). Pre-existing custom company roles need the new permissions ticked in the Roles matrix (see §7).
  • Decisions D1–D6 were implemented per the recommended defaults (reject conflicting starts; later-of-both late source; last-valid-OUT-after-grace checkout; server+agent gate/tamper; live screenshot refresh; server-offset clock). Confirm the defaults suit each client, or set per-company overrides where provided.
